# Factor column catalog

[Chinese version](https://runchengxie.github.io/money-trees/zh-CN/factor-catalog/)

This page explains how to use the complete column-level catalog. The machine-readable catalog is [factor-catalog.csv](factor-catalog.csv), generated by `project_tools/generate_factor_catalog.py`.

## Coverage

| Factor family | Rows | Maintenance |
| --- | ---: | --- |
| Alpha101 / WQ101 | 101 | Kept in sync with `moneytree.factors.classic.build_alpha101_features`, using cross-sectional rank/scale semantics. |
| Alpha191 / GTJA191 | 191 | Kept in sync with `moneytree.factors.classic.build_alpha191_features`, using cross-sectional rank/scale semantics. |
| Alpha158 local baseline | 158 | Kept in sync with `moneytree.factors.qlib.build_alpha158_features`; each row includes the local formula. |
| Alpha360 local baseline | 360 | Kept in sync with `moneytree.factors.qlib.build_alpha360_features`; each row includes the local formula. |

The catalog contains 810 rows. Alpha101/191 formulas are maintained by the local Python factor functions in `src/moneytree/factors/classic.py`, with cross-sectional rank/scale grouped by trading date.

Alpha101/191 have two generation paths: local Python generation through `moneytree.factors.classic`, and external generation through modules under `docker/dolphindb/modules/`. Their rank/scale, missing-value, and processing semantics differ. Before production use, compare the paths on a small sample. The recommended output is a standard `date, ticker` panel or factor store; see [classic Python Alpha generation](classic-alphas-python.md) and [DolphinDB Alpha generation](generate-alpha101-191-with-dolphindb.md).

## CSV fields

| Field | Meaning |
| --- | --- |
| `family` | Factor family: `alpha101`, `alpha191`, `alpha158`, or `alpha360`. |
| `column` | Recommended or actual column name in the panel. |
| `group` | Broad group such as `external_formula`, `candlestick`, `momentum`, or `sequence_lag`. |
| `count_scope` | Number of columns in the family, used for completeness checks. |
| `input_fields` | Core input fields required by the column. |
| `formula_status` | `implemented_local` or `external_dolphindb_module`. |
| `formula_source` | Formula source or integration source. |
| `formula_or_rule` | Local calculation rule or external-factor integration description. |
| `generation` | `external` or an in-repository generation function. |
| `notes` | Adjustment, normalization, missing-value, or upstream implementation notes. |

## Semantics

Local Alpha158/360 defaults to `adjusted=True`. Price fields prefer `open_adj/high_adj/low_adj/close_adj/vwap_adj`; when adjusted columns are unavailable, the implementation falls back to unadjusted fields. `volume` always uses raw volume.

For Alpha101/191 rows, `formula_status` is `implemented_local` and `formula_source` points to `src/moneytree/factors/classic.py`. The `formula_or_rule` field states that the factor is generated locally in Python. Rank/scale is calculated cross-sectionally by trading date, while `ts_*` rolling operators run along each security's time series. The DolphinDB path remains available and may produce different results.

Alpha158 `amount_ma_*` features depend on `amount`; if the panel has no `amount`, the implementation approximates it with `close * volume`. Alpha360 price lags use `shift(field, lag) / current_close - 1`, while volume lags use `shift(volume, lag) / current_volume - 1`.

All model features remain subject to the training configuration's `feature_lag_periods`. The default is `feature_lag_periods=1`, meaning a signal visible after the T-day close is used one day later.
