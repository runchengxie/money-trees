# Alpha 810 研究层边界设计

## 背景

`money-trees` 当前同时承担经典 Alpha 因子生成、数据接入、模型训练、组合构造、滚动回测和研究产物输出。与此同时，`quant-platform` 已经提供策略无关的组合、风险、回测和执行模拟，`quant-backtest-runtime` 已经提供回测任务执行、状态管理和结果发布能力。继续让 `money-trees` 保持完整回测平台定位，会造成职责重叠、接口重复和公开发布边界不清。

## 目标

将 `money-trees` 收窄为 **Alpha 810 因子计算与研究证据生产层**，保留它对 Alpha101、Alpha191、Alpha158 和 Alpha360 的专长，同时把通用回测与任务运行职责交给现有 Quant 系列项目。

第一阶段不进行大规模删除或破坏性迁移，而是先建立清晰的公共边界、可复现的因子评估输出和静态公开快照，为后续拆除重复模型/回测逻辑提供稳定接口。

## 非目标

- 不在 `money-trees` 中实现订单撮合、执行仿真或生产任务队列。
- 不把 `quant-platform` 改造成模型训练框架；其职责仍然是策略无关的组合、风险、回测和执行机制。
- 不把真实数据、原始缓存、逐股票信号、组合权重、凭证或私有研究参数提交到 GitHub。
- 不让 GitHub-hosted Actions 直接依赖本地硬盘盒；本地数据只能通过受控的离线生成步骤进入公开快照。
- 不在第一阶段彻底删除当前模型训练和回测代码；先通过适配层和文档建立迁移路径，避免破坏现有用户。

## 目标架构

```text
quant-market-data-platform / 本地数据发布
              |
              v
        money-trees
  因子生成、目录、校验、单因子评估
              |
              +--> 因子值/信号/评估证据导出
              |          |
              |          v
              |   quant-research（模型训练、研究假设、晋升规则）
              |          |
              |          v
              |   quant-platform（组合、风险、回测、执行模拟）
              |          |
              |          v
              |   quant-backtest-runtime（任务执行与结果归档）
              |
              +--> 脱敏静态快照 --> Alpha 810 GitHub Pages
```

## `money-trees` 保留的职责

### 1. 因子计算与因子仓库

保留 Alpha101/191/158/360 的生成入口、列名目录、输入字段校验、因子仓库写入和元数据清单。因子计算结果必须能够关联：

- 因子族和因子名称；
- 生成器/实现版本；
- 输入数据版本；
- 覆盖区间、股票数量和缺失率；
- 计算口径和横截面/时间序列语义。

### 2. 单因子研究证据

提供不依赖特定策略模型的基础评估：IC、RankIC、分组收益、覆盖率、换手代理、时间稳定性和分阶段统计。输出应为可审计的 JSON/Parquet/CSV 产物，并携带数据、配置和代码版本摘要。

### 3. 轻量验证信号

可以保留一个最小的分组或排序信号验证器，用于确认“因子值能否形成可解释的研究信号”。它不负责替代 `quant-platform` 的完整策略回测，也不负责生产模型训练。

## 移出或降级的职责

- 随机森林、XGBoost、线性模型等训练适配器：长期归入 `quant-research`；第一阶段保留兼容入口和迁移文档。
- 滚动训练、留出验证和模型驱动组合构造：归入研究层，不再作为 `money-trees` 的核心公共承诺。
- 通用组合权重、风险约束、交易成本、执行模拟和账本：调用 `quant-platform`。
- 任务排队、worker、状态、资源限制和结果发布：调用 `quant-backtest-runtime`。

## 公开展示设计

建议新增一个独立的 Alpha 810 展示站或在现有公开因子展示站中增加入口。交付分为两层：MkDocs 承载稳定的项目说明、数据契约、研究口径和复现指南；现有 Vite/React 站点承载因子目录、图表和交互式研究结果。两者都由 GitHub Actions 构建发布，但不共享运行时计算逻辑。

第一阶段采用静态快照，不在线计算：

1. 在本地或稳定的受控机器上读取硬盘盒中的数据。
2. 运行因子生成和单因子评估。
3. 运行公开发布审计，删除原始路径、凭证、逐股票信号和私有参数。
4. 只发布聚合后的静态 JSON/CSV/Parquet 和图表数据。
5. GitHub Actions 分别构建 MkDocs 文档和 Vite/React 站点，并发布到 GitHub Pages。

首版页面包括：因子目录、因子详情、IC/RankIC、分组累计收益、覆盖率/缺失率、相关性概览、数据版本和研究口径。文档站包括项目边界、因子快照 schema、生成命令、公开发布审计、数据版本和方法局限。每个页面都必须显示样本区间、数据版本、计算时间和“研究证据不等于未来收益承诺”的声明。

## 分阶段交付

### 阶段一：边界与证据出口

- 更新 README 和架构文档，明确 `money-trees` 的 Alpha 研究层定位。
- 建立 MkDocs 文档入口和 GitHub Actions 文档发布流程。
- 增加稳定的单因子评估输出契约和脱敏公开快照格式。
- 增加一个最小静态展示站或为 `quant-factor-observatory` 定义 Alpha 810 数据入口。
- 用合成数据覆盖发布审计和页面构建，不接触真实数据。

### 阶段二：连接通用平台

- 将轻量验证信号转换为 `quant-platform` 可消费的标准信号/策略输入。
- 用 `quant-platform` 完成组合、风险和完整回测。
- 用 `quant-backtest-runtime` 提交、运行和归档正式任务。
- 在 `money-trees` 中保留清晰的 adapter，而不是复制通用回测逻辑。

### 阶段三：训练层收敛

- 将模型训练实现迁移或重建到 `quant-research`。
- 为现有 `money-trees` 用户保留兼容期和迁移说明。
- 在确认下游无依赖后，再删除重复的模型、组合和滚动回测实现。

## 接口原则

- 因子产物必须带数据版本、代码版本、配置摘要和 schema 摘要。
- 跨仓库只通过版本化文件/JSON 契约或已发布包协作，不引用开发 worktree 路径。
- 公开发布默认只允许聚合统计和示例曲线；逐股票因子值、组合权重和原始输入禁止进入公开仓库。
- 所有正式回测必须能够追溯到因子产物版本、研究配置和回测运行版本。

## 第一阶段验收标准

- README 能准确说明 `money-trees`、`quant-platform`、`quant-backtest-runtime` 和研究层的职责边界。
- 合成数据能够生成至少一个因子的聚合评估快照，并通过公开发布审计。
- 快照包含因子名称、样本区间、覆盖率、IC/RankIC、分组收益和版本元数据。
- 页面可以从静态快照构建，不需要真实数据、凭证或运行时回测服务。
- MkDocs 文档可以在 GitHub Actions 中独立构建并发布，且包含快照 schema 和发布审计说明。
- 现有 `money-trees` 回测 CLI 和测试仍保持兼容；删除重复能力留到后续阶段。
